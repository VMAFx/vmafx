- Completed the ADR-1281 PyTorch 2.14 migration. Every `ai/` ONNX export now runs through one shared dynamo bridge (`aiutils.onnx_export`) that really does publish the registry's opset-17 contract: it labels shared dynamic axes without tripping the exporter's fatal symbol-collision `UserWarning`, repairs the `noop_with_empty_axes` attribute ONNX's version converter leaves on down-converted reductions — which had been producing graphs that claimed opset 17 while failing ONNX's checker and ONNX Runtime's loader — validates every graph before publishing it, and writes it atomically. Quantization-aware training moved to torchao 0.18 PT2E with a repository-owned type stub for the surface it calls. `ai/train/train.py` run as a script now resolves `aiutils` from its own checkout; the online sidecar trainer no longer broadcasts a scalar target against a one-element prediction on single-sample batches; and the vmaf-tune predictor tests assert the documented synthetic-stub warning instead of tripping over it. The QAT, ONNX-export, and agent-facing documentation now describes the pipeline that actually runs (ADR-1281).
