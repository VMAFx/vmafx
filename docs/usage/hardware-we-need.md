# Hardware we need reports from

VMAFx runs on more processors and graphics cards than the project owns. Its GPU
code in particular is proven bit-exact on one card per vendor, and the project cannot
buy the rest. If you have one of the machines in the table below, one command gives
the project a report it cannot produce itself, and you can be credited for it.

## What to do

1. Find your hardware in the table. A row says which package to run.
2. Follow that package's section of the [tester guide](tester-image.md). You build
   nothing and install no toolchain; you run one container image (or, on a Mac or a
   Windows PC, one archive) and it prints a JSON report.
3. Open a [hardware report issue](https://github.com/VMAFx/vmafx/issues/new?template=hardware_report.yml)
   and attach the report. A report with verdict `fail` is welcome: it is a finding.

If your machine is not in the table, run the [container image](tester-image.md#b-container-image)
anyway; it works on any machine with Docker and records the processor it ran on.

## The table

Each row is a hardware family, the package that tests it, the open row of the
project's [bug ledger](../state.md) that a report closes, and where the row stands.
"Covered" means a project host already measures the family; a report from your
machine still repeats the measurement on different silicon and is welcome.

## Where the status comes from

The table is generated, not hand-kept. `scripts/docs/generate-hardware-reports.py`
reads every report under [hardware reports](../hardware-reports/index.md), decides for
each report which rows it counts for (the processor's dispatch flags for a CPU row, the
GPU family the report measured for a GPU row), and prints the number of reports and the
worst verdict. The verdict is the one of the checks the row is about, not the report's
overall verdict: a CPU row reads the dispatch and reference equivalence checks, the unit
tests, the golden check and whether the package's files match its build (the native
macOS row adds the Metal equivalence and the Metal gate, since it closes the Metal rows),
and a GPU row reads its device's result. A report whose GPU section fails therefore still
counts as a pass for its processor's row. `make docs-fragments-check` fails when the table
is stale. The families,
packages and ledger rows come from `scripts/docs/hardware-needs.json`; the generator
refuses a GPU family of the tester image's row maps that has no row there, and a
ledger id that does not exist.

A row that says "no report yet" can still have been tested by someone who did not send
the report. Only a report in [hardware reports](../hardware-reports/index.md) counts.

## Which machine is whose

The project's own hosts, which the "covered" rows name: an RTX 4090 (Ada), an Arc A380
(Xe-HPG), the small RDNA2 graphics of a Ryzen 7000 (`gfx1036`), a Ryzen 9 9950X3D
(Zen 5, AVX-512), and an Arc B580 and an Arc Pro B60 (Xe2) on the maintainer's home
cluster. No project host is an Apple Mac, a Windows machine, an Arm server, an Intel
processor with AVX-512, or an NVIDIA, AMD or Intel card of another family.
