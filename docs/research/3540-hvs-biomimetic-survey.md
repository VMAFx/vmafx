## Question

Which mechanisms of the human visual system (HVS) could improve VMAFx quality prediction beyond the mechanisms its extractors already implement, and what experiment could reject each proposal?

## Findings

### Start here

Start with the [five ranked experiments](#five-experiments-ranked-by-expected-gain-per-effort), then use the topic tables to select a mechanism and its acceptance test. The 22 leads are proposals, not measured improvements. Repository observations refer to commit `6c48e8a68e68bd60de626b10eca3e6ae6e64a01d`; literature and dataset pages were opened on 2026-11-12. The [source ledger](#sources) distinguishes abstracts from method sections actually read.

An available extractor is not automatically part of a fused quality score: [`model/vmaf_v0.6.1.json`](../../model/vmaf_v0.6.1.json) names ADM2, motion2 and four VIF scales. New features need an explicitly trained model before claims about the fused score are possible. The tables instead name the standalone score or experimental fusion to compare. Existing default scores and golden assertions remain the control, following the [golden-data rule](../development/agent-hard-rules.md).

**Reading the tables.** S means less than one week for a parameter or pooling experiment; M means a new extractor or model retraining; L means a new model family, corpus or subjective study. These are scope estimates, not delivery promises. **U** in a licence cell means reference code or weights were not licence-audited: implement from the paper in a clean room, use authors' code only as an oracle where its terms permit execution, and do not copy code or redistribute weights. A paper's publication licence does not establish its implementation's licence. Existing file notices remain authoritative; see [`REUSE.toml`](../../REUSE.toml).

### Five experiments ranked by expected gain per effort

This is a qualitative prioritisation inferred from the gaps and reuse opportunities below, not a numerical gain forecast.

1. **C1 — expose adapting luminance to existing Barten ADM (S):** [`float_adm.c`](../../core/src/feature/float_adm.c) supplies a fixed luminance despite the existing CSF accepting one, making a standalone UPIQ calibration experiment small and directly testable.
2. **P1 — calibrate existing channel norms and percentiles (S):** [`adm_tools.c`](../../core/src/feature/adm_tools.c) and [`libvmaf.c`](../../core/src/libvmaf.c) already supply the reductions, so a held-out comparison can reject ineffective settings without introducing an extractor.
3. **P2 — compare recency and hysteresis pooling (S):** reuse per-frame scores and the LIVE Mobile dynamic-quality data [D5](#dataset-ledger); keep the two memory mechanisms separate and treat short-clip results cautiously [S20](#paper-ledger).
4. **M2 — add a normalised Laplacian distance feature (M):** local division offers a concrete alternative to ADM's subtractive masking, with a direct TID2013 test [S07](#paper-ledger), [`adm_tools.c`](../../core/src/feature/adm_tools.c).
5. **G1 — make the existing DISTS path locally texture-adaptive (M):** the scalar ONNX bridge already exists, so the experiment tests local structure/texture allocation rather than proposing DISTS again [S16](#paper-ledger), [`feature_dists.c`](../../core/src/feature/feature_dists.c).

### 1. Retina and photoreceptor adaptation

**What VMAFx already models.** [`pu21.c`](../../core/src/feature/pu21.c) decodes full-range PQ luma into absolute luminance and scores a PU21 encoding, while [`pu21_math.h`](../../core/src/feature/pu21_math.h) includes `banding_glare` and other coefficient sets. [`pu21_ssim.c`](../../core/src/feature/pu21_ssim.c) adapts SSIM stabilisation to that encoding. This is already an HDR sensitivity adapter; a second generic PU transform is redundant. The ADM helper already has a combined rod/cone sensitivity term and frequency-domain optical attenuation, but these are not separately adapted receptor channels or a scene-dependent spatial veil [`barten_csf_tools.h`](../../core/src/feature/barten_csf_tools.h). These inspected paths do not maintain rod/cone-specific adaptation state. PU21's glare adjustment and HDR-VDP's optical scatter are different models [S02, S03](#paper-ledger).

For R1, a candidate Naka–Rushton form is `R(L) = L^n / (L^n + sigma^n)`, with locally adapted `sigma`; `n = 1` has the Michaelis–Menten saturation form. This is the proposed parameterisation, not a fitted human model. R1 must also test whether it double-counts the luminance adaptation already represented by PU21 [S01, S03](#paper-ledger), [`pu21_math.h`](../../core/src/feature/pu21_math.h). HDR-VDP-2 explicitly excludes temporal processing, so its static validation does not establish light/dark adaptation kinetics [S02](#paper-ledger).

### 2. Contrast sensitivity

**What VMAFx already models.** [`adm_options.h`](../../core/src/feature/adm_options.h) declares Watson97, Barten and native ADM CSFs, display height, viewing distance and a default luminance of `100.0` cd/m². [`adm_csf_rfactor_s`](../../core/src/feature/adm_tools.c) selects their band weights; [`float_adm.c`](../../core/src/feature/float_adm.c) currently passes the constant luminance. [`y_funque_plus.c`](../../core/src/feature/y_funque_plus.c) also weights wavelet detail bands with a CSF. The Barten helper is a simplified HDR-VDP-2.2.1-derived model, including a combined rod/cone term and MTF; its CSF-shape interpolation clamps luminance to anchors from `0.002` to `150` cd/m², while its combined rod/cone amplitude term uses the original luminance argument [`barten_csf_tools.h`](../../core/src/feature/barten_csf_tools.h). Thus “add a spatial CSF” is already covered; the opportunities are calibration and joint space/time/luminance sensitivity. Barten and Daly VDP are useful comparators discussed in stelaCSF, not new implementations verified here [S05](#paper-ledger).

castleCSF extends the multidimensional treatment to colour; its chromatic use is F1 below [S04](#paper-ledger). Detection-threshold fits are not themselves evidence of improved suprathreshold quality prediction [S05](#paper-ledger).

### 3. Spatial masking

**What VMAFx already models.** [`adm_cm_thresh3x3_s`](../../core/src/feature/adm_tools.c) sums neighbouring CSF-filtered responses across three orientations; `adm_cm_s` subtracts that threshold before norm pooling. ADM therefore already has local and cross-orientation masking. [`vif_pixel_statistic_s`](../../core/src/feature/vif_tools.c) uses local variances, covariance, gain and residual/noise terms for information-fidelity scoring; texture sensitivity is not absent there either. [`psnr_hvs_score.c`](../../core/src/feature/psnr_hvs_score.c) supplies CSF/mask arithmetic. The new experiments distinguish divisive gain control and cross-scale context from those existing operations.

### 4. Temporal masking

**What VMAFx already models.** [`integer_motion_v2.c`](../../core/src/feature/integer_motion_v2.c) computes blurred reference-frame differences and exposes motion windows and frame-rate weighting. [`speed.c`](../../core/src/feature/speed.c) has temporal entropic differencing; [`speed_qa.c`](../../core/src/feature/speed_qa.c) has distorted-frame temporal entropy. [`y_funque_plus.c`](../../core/src/feature/y_funque_plus.c) emits a temporal MAD atom. [`transnet_v2.c`](../../core/src/feature/transnet_v2.c) emits shot-boundary estimates using delayed windowed inference. These are reusable signals; the inspected files do not establish a psychophysically calibrated asymmetric masking kernel or a motion-dependent flicker visibility predictor. The C wrapper [`tad_rust.c`](../../core/src/feature/tad_rust.c) alone is insufficient evidence about its Rust implementation's perceptual coverage.

### 5. Foveation and saccadic suppression

### 6. Colour opponency

**What VMAFx already models.** [`ciede.c`](../../core/src/feature/ciede.c) computes CIEDE2000 after a BT.709-assuming Lab conversion; [`delta_e_itp.c`](../../core/src/feature/delta_e_itp.c) computes a mean PQ-based ITP colour distance. [`ssimulacra2.c`](../../core/src/feature/ssimulacra2.c) uses LMS-derived XYB channels and a multiscale error model. Thus colour sensitivity is present, but a pixel-distance mean is a different operation from chromatic CSF filtering and cross-channel masking. Colour-space choice alone does not establish quality accuracy [S13, S14, S21](#paper-ledger).

### 7. Texture and grain perception

**What VMAFx already models.** [`feature_dists.c`](../../core/src/feature/feature_dists.c) already registers `dists_sq` with a two-input ONNX model; this bridge alone does not establish which learned weights are available. ### 8. Cortical and quality-aware pooling

**What VMAFx already models.** [`adm_tools.c`](../../core/src/feature/adm_tools.c) has multiscale oriented bands and configurable `adm_p_norm`, including the default cubic path; [`ms_ssim.c`](../../core/src/feature/ms_ssim.c) and [`ssimulacra2.c`](../../core/src/feature/ssimulacra2.c) combine multiple scales. [`libvmaf.c`](../../core/src/libvmaf.c) provides mean, harmonic mean, extrema and linearly interpolated percentiles/median. Side-data weights affect the mean/harmonic paths; [Research-1188](1188-percentile-pooling-methods.md) explicitly distinguishes their semantics from percentiles. These are existing operations, not missing features. These multiscale channels approximate aspects of V1 processing; a successful norm fit would not identify a biological pooling exponent [S07](#paper-ledger). Spatial channel pooling approximates early cortical processing; recency and hysteresis concern temporal memory, a different level of explanation [S06, S20](#paper-ledger).

## Evaluation contract

The following are proposed experimental rules, not results from this research run.

- Use **reference-content-disjoint** development/test splits; keep all distortions, encodings and grain seeds from one source together. UPIQ incorporates earlier datasets, so testing on a constituent after fitting UPIQ is not independent [D1](#dataset-ledger).
- Report Spearman rank-order correlation (**SROCC**), Pearson linear correlation (**PLCC**) and, where useful, Kendall rank-order correlation (**KROCC**). Set score direction against MOS/DMOS before evaluation. Fit any PLCC mapping on development data, freeze it for held-out evaluation, and state that protocol explicitly.
- For a lead to support a gain claim, require a positive paired difference with a content-bootstrap 95% confidence interval excluding zero on its declared primary metric. Report the complete dataset as well as the named stratum, sample counts and uncertainty; do not choose strata after inspecting outcomes. A small corpus may return an inconclusive result.
- Hold colour conversion, display luminance, viewing distance, frame alignment and pixel format constant between ablations. Express temporal windows in seconds and spatial frequencies in cycles per degree. HDR and foveated models require physical viewing information [S04, S05, S10, S21](#paper-ledger).
- Compare additions against the existing extractor and an otherwise identical fusion without the addition. For every implementation, include positive distortion cases, negative controls and boundary cases: identical pairs, neutral weights, flat/black/bright images, shuffled saliency, clip ends, cadence changes and missing gaze. These tests are proposed acceptance work, not checks introduced or executed here.
- Do not assign old MOS to newly generated stimuli. Cut-timed, eye-tracked and grain-synthesis experiments require new subjective labels; generic quality datasets can support a screening experiment but cannot prove those mechanisms. Public availability also does not imply unrestricted redistribution [D2–D6](#dataset-ledger).

## Alternatives explored

- **Re-add CSF, masking, PU21, DISTS or percentiles.** Rejected as a research direction: the source inspection above found each capability. Leads extend a particular missing dependency or test a new calibration instead [`adm_tools.c`](../../core/src/feature/adm_tools.c), [`pu21.c`](../../core/src/feature/pu21.c), [`feature_dists.c`](../../core/src/feature/feature_dists.c), [`libvmaf.c`](../../core/src/libvmaf.c).
- **Replace the existing fusion with an entire visual difference predictor.** Retain HDR-VDP-2, FovVideoVDP and ColorVideoVDP as paper/oracle comparisons first; their physical inputs and output calibration differ from the existing six-feature model [S02, S10, S21](#paper-ledger), [`model/vmaf_v0.6.1.json`](../../model/vmaf_v0.6.1.json).
- **Use one scalar saliency score for foveation and saccades.** Rejected: the map mean discards spatial position, and a spatial attention estimate contains no measured eye velocity [`feature_mobilesal.c`](../../core/src/feature/feature_mobilesal.c), [S10, S12](#paper-ledger).
- **Assume a more elaborate temporal pool always wins.** Rejected: S20 finds dataset-dependent performance and little recency benefit on short clips. Its blind-VQA setting also needs a new full-reference test before adoption [S20](#paper-ledger).
- **Optimise all additions at once.** Defer: a positive fusion result would not identify the contribution of adaptation, masking or pooling. The proposed evaluation contract requires isolated ablations before a combined model.
- **Copy reference code because its paper is public.** Rejected: publication access and software/weight redistribution are separate questions. All U-marked leads use paper-derived implementations and conditional oracle comparisons until licence evidence is available [`REUSE.toml`](../../REUSE.toml).

## Open questions

- What target viewing conditions and score interpretation should govern the first model: SDR streaming quality, absolute-photometric HDR quality, or wide-field foveated quality? Their required inputs differ [S02, S10, S21](#paper-ledger).
- Are display spectra and low-light adaptation measurements available for R2, and is a mesopic subjective study justified before simpler luminance-conditioned models have been rejected?
- Which model/weight artefacts actually accompany the in-tree DISTS-Sq and saliency bridges, and under which licences? File registration alone establishes neither trained accuracy nor export rights [`feature_dists.c`](../../core/src/feature/feature_dists.c), [`feature_mobilesal.c`](../../core/src/feature/feature_mobilesal.c).
- Can the declared dataset access routes supply paired media, subjective labels and viewing metadata under acceptable terms? D3–D8 have access or scope questions; no download was attempted.
- Will a sufficiently powered long-duration corpus be needed if LIVE Mobile pooling results are inconclusive? Its dynamic-rate clips offer an initial test, not a universal memory model [D5](#dataset-ledger), [S20](#paper-ledger).
- What causal latency budget is acceptable for backward masking and hysteresis? T1 and some P2 definitions require future context [S08, S20](#paper-ledger).
- Full method/parameter reading remains necessary for abstract-only S01 and S06 before implementation; all external implementation/weight licences remain unverified.
