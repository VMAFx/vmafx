| [ADR-1126](1126-retire-isort-for-ruff.md) | Retires the standalone `isort` pre-commit hook, the `isort` step in the `Python Lint` CI job, and the `[tool.isort]` block in `pyproject.toml`; ruff's `I` ruleset (already selected, already enforcing `I001`) becomes the sole import sorter. The repo ran two independent isort implementations over the same files and, because both auto-fix, `pre-commit run --all-files` never reached a fixed point on `master`: isort rewrote a file and ruff rewrote it back, so the required `Pre-Commit (Formatters + Basic Checks)` check failed with a net-zero `git diff` — which is why it read as a flake. Two genuine behavioural differences, not misconfiguration: (1) for a per-member trailing comment (`from m import (x,  # type: ignore[...])`) isort collapses to one line (89 chars, under the shared 100-char limit) while ruff re-splits to keep the comment attached; (2) given both `from X import (a, b)` and `from X import y as z`, isort orders the alias statement first and ruff second. Setting `combine_as_imports` in both configs was measured and rejected — it churns 8 files and still oscillates, fixing only the second case. Lands as a configuration-only change: `master` is already ruff-clean, verified by three consecutive ruff+black rounds producing an empty `git status`. | Accepted | ci, build, docs, fork-local |
