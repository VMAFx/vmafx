| [ADR-1254](1254-win64-cannot-realign-the-stack.md) | Wide vector register pressure is a Win64 correctness constraint, not a performance one. The MS x64 ABI guarantees only 16-byte stack alignment and its unwind contract prevents the `and $-64, %rsp` realignment gcc emits on SysV, but gcc's MinGW target still allocates 64-byte-aligned `zmm` spill slots addressed off `%rsp` — so `ssim_accumulate_avx512` faulted (#GP, reported by Windows as a read of `0xFFFFFFFFFFFFFFFF`) on most call paths. Present in gcc 14.2.1 and 16.2.0; `-mstackrealign` and `-mprefer-vector-width=256` were measured and do not help. The kernels now rebuild their broadcast constants per block instead of holding them live, and `scripts/ci/check-win64-stack-alignment.py` disassembles the built Windows objects so the class cannot return on a path CI's AVX-512-less runners never execute. | Accepted | simd, build, windows, ci |
