| [ADR-1189](1189-score-at-index-eagain-contract.md) | `vmaf_score_at_index`, `vmaf_score_at_index_model_collection` and `vmaf_feature_score_at_index` report an in-flight frame as `-EAGAIN`. The GPU path is double-buffered — frame N is collected during frame N+1 — and the three per-index readers had no in-flight check, so the model paths fell through to `vmaf_predict_score_at_index` and predicted over a partially written feature row. The readers now return `-EAGAIN` when a registered extractor still has un-collected work for exactly that index; callers flush with `vmaf_read_pictures(NULL, NULL, 0)` and retry. Rejected alternatives: fencing inside the getter (would have to run `collect()`, which double-writes the collector on the next frame's Phase 1) and `vmaf_thread_pool_wait` (deadlocks a reader called from a metadata callback, which runs on a pool worker). Post-flush reads — including the whole Netflix golden gate — are unaffected. | Accepted | api, cuda, gpu, contract |
