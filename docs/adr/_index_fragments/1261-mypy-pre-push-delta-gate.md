| [ADR-1261](1261-mypy-pre-push-delta-gate.md) | The local pre-push type check fails only on findings a branch introduces. `mypy` in CI is advisory by design (uneven numpy / pandas / torch stub coverage), so a blocking local hook that reported inherited findings was stricter than the gate it mirrors: it rejected 14 findings that `master`'s own copies of the same files produce, and no branch touching `ai/src/` could be pushed at all, because a `mypy_path` base gives those files two module names. Files under `ai/src/` now get their own `--explicit-package-bases` run, the same files are re-checked at the merge base in a disposable worktree, and only new findings fail; an unattributable non-zero exit still fails closed. Raising `python_version` from 3.10 to the required 3.14 unmasks 175 findings on `master` and is left to its own change. | Proposed | ci, hooks, python, tooling, fork-local |
