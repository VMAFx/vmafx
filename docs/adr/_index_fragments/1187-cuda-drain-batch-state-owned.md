| [ADR-1187](1187-cuda-drain-batch-state-owned.md) | The CUDA drain batch is owned by `VmafCudaState`, not by the OS thread. The T-GPU-OPT-1 fence batch stored its registration table in a `static _Thread_local` struct, but every entry aliases a `CUevent` and a `bool *` owned by an extractor bound to a specific `VmafCudaState` — thread scope is strictly wider than the handles it holds. The frame loop deliberately returns with the batch open, so an abandoned or errored `VmafContext` left destroyed events and freed flag pointers in a batch that the next `VmafContext` on that thread flushed (`T-UPSTREAM-1305`, Netflix/vmaf#1305). `VmafCudaDrainBatch` moves into `VmafCudaState::drain_batch` (opaque public type — no ABI break), every drain entry point takes the owning state, teardown empties the batch instead of only dropping the drain stream, and `vmaf_close()` runs a best-effort flush + close *before* `feature_extractor_vector_destroy()`. Scheduling-only: the same events are waited on in the same order, so bit-exactness is untouched. Also folds in the inverted stream-priority clamp in `common.c` (`MAX(low, MIN(high, prio))` collapsed to the *lowest* priority; CUDA's scale is inverted). | Accepted | cuda, gpu, lifetime, memory-safety |
