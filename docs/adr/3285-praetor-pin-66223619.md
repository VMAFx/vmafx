# ADR-3285: Move the praetor pin to 6622361940dc and refresh the register skills

- **Status**: Accepted
- **Date**: 2026-10-12
- **Deciders**: lusoris
- **Tags**: ci, governance, standards

## Context

`PRAETOR_REF` in `.github/workflows/standards-gate.yml` names the praetor engine
that CI installs and that the governance hooks run through the launcher
([ADR-3272](3272-praetor-pin-9bf502ec-engine-launcher.md)). The pin was
`9bf502ec6ce5`. Praetor's main is four commits further on:

| Praetor commit | What it brings here |
|---|---|
| `d5b64b519` (cordanaLLM/praetor#1258) | The register skills `adopt` ships (`adhd-format`, `caveman`, `social-text`) pass markdownlint's default rules: the same text, wrapped at 80 columns, with blank lines around lists. |
| `8462ce135` (cordanaLLM/praetor#1274) | The commit-message and pull-request checks refuse a closing keyword that would close someone else's pull request. No gate here runs `forge check-commits`, `forge check-message` or `forge validate-pr`, so nothing changes in this repository yet. |
| `ca6e5ce33` (cordanaLLM/praetor#1276) | Praetor's own gating builds go below an absolute `CARGO_TARGET_DIR`, never in it. Nothing here sets that variable for a governance command. |
| `662236194` (cordanaLLM/praetor#1286) | Praetor's committed devcontainer bundle is regenerated. This repository keeps its own dev container (`dev/Containerfile`) and takes nothing from it. |

`praetorctl audit --offline` reports the same 143 warnings with both engines,
line for line: 142 "Workflow triggers" and one about cache-band markers in
`AGENTS.md`. Both engines were run on a clean clone at the branch base
`5942ed2f7`.

## Decision

Move `PRAETOR_REF` to `6622361940dc66399d027f3a203884bce2f616ac` under
[ADR-1351](1351-praetor-engine-pin-move.md)'s conditions and take praetor's
refreshed files at that commit.

- **Refreshed praetor files.** The six skill files
  `.agents/skills/{adhd-format,caveman,social-text}/SKILL.md` and
  `.claude/skills/{adhd-format,caveman,social-text}/SKILL.md` are praetor's
  bytes, taken from `praetorctl adopt --lock-source-root=<praetor clone at the
  pin>` in a throwaway clone without `--force`. Nothing else `adopt` wrote
  differs from this tree apart from the two entries below.
- **Not copied back.** `.claude/settings.json`, `.codex/hooks.json` and
  `.gemini/settings.json`: the pre-tool guard `adopt` registers there lands in
  a change of its own, as ADR-3272 recorded. `.config/lefthook/python.sh`:
  `adopt` writes it for its own `lefthook.yml`, and this repository keeps its
  `lefthook.yml`, which does not call it.
- **Kept.** The launcher `.config/lefthook/engine.sh`, `.config/praetor/engine.mk`
  and their two dated exceptions are unchanged at this pin.

## Alternatives considered

| Option | Why not |
|---|---|
| Keep the pin at `9bf502ec6ce5` | The skills this repository ships would stay the older text, which praetor no longer distributes, and the next pin move would carry two engines' changes at once. |
| Adopt at `d5b64b519` only | The three later commits change nothing here, so stopping short only leaves a second, smaller pin move for later. |
| Format the skills here | They are praetor's text; an edited copy stops following the pin. |
| Copy `.config/lefthook/python.sh` too | Nothing in this repository calls it; an unused praetor file would be one more file to keep at the pin. |

## Consequences

- **Positive**: CI and the hooks run praetor's current main. The skills match
  what praetor ships to every repository that adopts them.
- **Neutral**: audit's findings are the same 143 warnings with both engines.
- **Neutral / follow-ups**: the pre-tool guard in the agent settings is still a
  change of its own (ledger `vmafx-adopt-pretool-hook`). Once this repository
  runs praetor's forge checks, the closing-keyword refusal of #1274 applies to
  its commit messages and pull request texts.
