# pkg/modeleval — agent notes

Native Go implementation of MCP `eval_model_on_split` + `compare_models`
tools. Replaces `python3 -c` helper `cmd/vmafx-mcp/impl.go` used to
shell out to (ADR-0704 Stage 2).

Reference implementation being ported:
`mcp-server/vmaf-mcp/src/vmaf_mcp/server.py::_eval_model_on_split` /
`_compare_models`.

## Load-bearing invariants

1. **Split hash frozen.** `split.go` must keep producing
   `sha256("vmaf-train-splits-v1:" + key)`, first 8 bytes big-endian,
   divided by 2^64, with `test < 0.1 <= val < 0.2 <= train`
   comparison chain in that order. Matches `vmaf_train`'s
   `split_keys` + Python MCP server. Any drift silently
   re-partitions every cached feature table, invalidates
   cross-language model comparisons. `split_test.go` asserts
   **bit-equality** against values generated by Python original —
   not tolerance assertions, never loosen them.

2. **Feature-column order = model's input contract.**
   `FeatureColumns` = canonical order (`adm2`, `vif_scale0..3`,
   `motion2`); columns absent from table skipped, survivors keep this
   relative order. ONNX graph fed `[rows, len(cols)]` tensor in
   exactly this layout — reordering slice silently feeds model
   transposed features.

3. **`Result` field order = wire format.** MCP layer serialises
   handler results with `json.MarshalIndent` — struct field order
   *is* JSON key order. Order mirrors Python dict's insertion order;
   `TestResultJSONKeyOrder` pins it.

4. **Statistics run float64; Python runs float32.** scipy does not
   upcast float32 arrays Python server hands it. Two implementations
   agree ~1e-7 on PLCC, ~1e-9 on RMSE, exactly on SROCC (rank-based).
   Documented, deliberate divergence — see package comment in
   `stats.go`. Never "fix" diff at that magnitude by reproducing
   numpy's float32 accumulation.

5. **Non-finite results = errors, not NaN.** `encoding/json` cannot
   marshal NaN — degenerate (zero-variance) input must fail loudly,
   never propagate. Deliberate divergence from Python, which emits
   invalid bare `NaN`.

## Generating goldens

scipy goldens in `stats_test.go` + `eval_test.go` produced with
scipy 1.18.1 / numpy 2.5.2. When regenerating from Go-side dump, parse
JSON as **float32 first**, then widen: Go writes shortest decimal
that round-trips as float32 — reading it straight into float64 yields
subtly different number, shifts PLCC by ~1e-8.

## ONNX inference lives elsewhere

Forward pass sits behind `Predictor` interface — keeps this package
pure Go, testable with `CGO_ENABLED=0`. Production implementation =
`pkg/libvmaf.DNNSession` (cgo), binds libvmaf's `vmaf_dnn_session_*`
API. Deliberately **no** third-party Go ONNX dependency: libvmaf
already links ONNX Runtime, applies model size cap + operator
allowlist (ADR-0211).
