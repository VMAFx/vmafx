# `tools/rc1-tester/` — Agent Operating Harness

## Invariants & Scope

1. **RC1 release boundary**: `tools/rc1-tester/` provides hardware probing, tool discovery, smoke validation, and shareable report bundling. same collector serves RC2 stabilisation candidate. It does **not** trigger performance benchmarks (RC8) or tiny-AI training pipelines (RC9).
2. **Rebase stability**: Hardware, toolchain, binary, and validation subprocesses must accept injected `runner` so their tests remain hermetic and offline.
3. **NASA JPL Rule 2 & Rule 4**: All production subprocess calls enforce explicit process-group timeouts and 1 MiB combined stdout/stderr ceiling through packaged `vmaf_rc1_tester.safe_process` module, so installed console command never depends on repository-only imports. No loops without bounds. Maximum function complexity $\le 10$, function length $\le 60$ LOC.
4. **Fail-closed backend correctness (HISS-07)**: Exit zero is not enough. PASS requires four consecutively numbered frames (through temporal frame 3), finite required model metrics, VMAF inside pinned model's `[0, 100]` clip range, consistent pooled metrics, and `backend_used` exactly matching explicit request. CPU must match pinned first-four-frame snapshot; each accelerator must match automatically run CPU reference within `5e-5` per metric and frame. ADR-1342 deliberately adopts ADR-0214's feature threshold for overall VMAF too; do not attribute that overall-score contract to ADR-0214. `backend_used` proves root state, not per-feature accelerator dispatch. pinned model/snapshot/fixtures are hashed. Missing evidence and silent fallback never pass. Exit code 100 (`VMAF_EXIT_BACKEND_INIT_FAILED`) remains `BACKEND_UNAVAILABLE` evidence per ADR-0498 and ADR-0543.
5. **No Netflix golden assertion modification**: Golden assertions in `python/test/` must never be touched.
6. **Report integrity and privacy**: `manifest.json` schema version is `1.0`. `SHA256SUMS` covers payload files other than itself and manifest; manifest repeats payload hashes and hashes `SHA256SUMS`; CLI prints whole-archive hash. Shared text redacts home/repository prefixes, archive metadata is normalized, and probes never request serial numbers or GPU UUIDs; documentation still tells testers to inspect reports before sharing.
7. **Tester image and macOS bundle (ADR-1492, ADR-1493)**: `hw_*.py`, `vmaf-tester-report` and `image/` are one report program for the container image (`docker/Dockerfile.tester`) and the macOS bundle (`scripts/ci/build-macos-tester-bundle.sh`); do not fork it per platform (HISS-19). Output is one JSON report with `schema_version` "2" (ADR-1496; "1" reports stay valid) validated by `docs/hardware-reports/report.schema.json` and `scripts/ci/check-hardware-reports.py`; a field change changes the schema, the gate and `tests/test_hw_*.py` together. Comparisons are `==` at `%.17g`, never a tolerance. `report_sha256` excludes `note` and itself. A missing own-architecture reference, a silent CPU fallback on `--backend metal` or a binary that differs from `image/build-info.json` fails closed; Metal `no_device` (vmaf exit 100) is not a failure. No host name, user name, serial number or UUID may enter the report: `/proc/cpuinfo`, `sysctl` and `system_profiler` are read through allow-lists. The macOS bundle needs no installed Python, so it ships a pinned interpreter; the report code stays standard-library only.
8. **Metal gate and state-row map (ADR-1496)**: macOS report runs the parity gate staged into `tester/gate/` (`image/prepare_build.py gate`; gate = stdlib only) as `--backends cpu metal --hold-exact metal` per fixture (`hw_gate.py`, section `metal_gate`, a check of the verdict), keeps per-case verdicts of tests printing `@case` lines (`hw_suites.py`, `unit_tests.cases`), and evaluates `image/metal-rows.json` (`hw_rows.py`, section `metal_rows`): row `pass` only when every named case / Metal metric / gate cell passed; a metric counts only when its extractor ran on Metal; a gate feature left out of a fixture with a recorded reason is no evidence. Row map held to `docs/state.md`, the Metal tests, the unit list and the gate by `core/test/test_metal_report_rows_contract.py`. `metal_rows` informs; closing a row = maintainer.
9. **Licences of the published packages (ADR-1503)**: `image/licensing.json` records every component of the tester image and the macOS bundle; `image/licensing.py check` fails their builds on a file no component claims, a Debian package without copyright file, a dist-info without licence file, an unrecorded, modified or source-less copyleft wheel graft, a compiled or repository file with a licence the component does not allow, an interpreter version without its `Doc/license.rst`, or notices missing a component, package or dist-info. A change that adds files to a package changes the record in the same PR. Vendor binaries ship unmodified (no `strip`, no `patchelf`). Notices are computed (`scan-build` reads `ninja -t deps` + SPDX headers / `REUSE.toml`), never hand-listed. A new kit = new artifact kind in `licensing.json` + negative test in `tests/test_licensing.py`. `licensing.py` is build-time only (Python 3.11+, `tomllib`); the report code stays 3.10-compatible.
10. **GPU section and Intel GPU image (ADR-1505)**: schema 3 adds one backend-neutral `gpu` section (`hw_gpu.py`); a GPU backend is a `GpuBackend` (`hw_sycl.py` for SYCL) registered in `GPU_BACKENDS` of `hw_report.py`, never a new top-level section. Per device: twins against the CPU of the same image at the gate's bound per feature (`image/gpu-twins.json`, written from the staged gate), gate cells held exact, device tests (`image/gpu-tests.json`), audits, rows of the backend's row map applied by device family. Every run of a device is pinned (`ONEAPI_DEVICE_SELECTOR=level_zero:<n>`) and each device test runs in a fresh directory under `/tmp`. `no_device` is not a failure and carries the missing `docker run` option. Device facts never hold a UUID, serial number or bus address (the CI gate refuses such keys). The Intel GPU image (`final-sycl` of `docker/Dockerfile.tester`) ships only the Intel runtime files of `image/sycl-runtime.json`, copied unmodified and checked against the compiler's `credist.txt`, and the compute runtime's Level Zero driver, IGC core, gmmlib and loader; no compiler, no OpenCL parts; its licence record is artifact `sycl-image` of `image/licensing.json` (`dpkg-foreign` for the Intel GPU stack, pinned `fetched_texts`), checked in stage `sycl-licence-check`. `sycl-rows.json` is held to `docs/state.md`, the `gpu` suite and the gate by `tests/test_gpu_rows_contract.py`.
11. **NVIDIA GPU image (ADR-1509)**: `hw_cuda.py` is the CUDA `GpuBackend` (devices from `hw_cudaprobe.py`: driver API via ctypes in a bounded child, PCI bus order, no UUID or bus ID; runs pinned `CUDA_VISIBLE_DEVICES=<n>` under `CUDA_DEVICE_ORDER=PCI_BUS_ID`; a device below compute capability 8.0 or without a cubin / PTX path of `image/cuda-targets.json` is listed, not run; no audit). `final-cuda` ships no NVIDIA file: `libvmaf` dlopens the host driver's `libcuda.so.1`, lent by the NVIDIA Container Toolkit (`--gpus all`, CDI `nvidia.com/gpu=all`) or WSL2; the `cuda-runtime` stage refuses any NVIDIA-named file, the `cuda-build` stage any binary whose `NEEDED` names one. Licence record = artifact `cuda-image`: component `nvidia-cuda-device-code` (no paths; CUDA EULA text from the copyright file of the package owning `libdevice.10.bc`, date-checked; notes pass on EULA 1.1.2 / 1.2) and `nv-codec-headers` (MIT notices copied from the headers); kernel objects `src/*.fatbin.c` take their `.cu` source's licence (`compiled_from` rule). `cuda-rows.json`: one row part per family (ampere, ada, hopper, blackwell), each holding every gate feature; `tests/test_gpu_rows_contract.py` covers it with `sycl-rows.json`. Workflow: matrix jobs `build-gpu` / `publish-gpu`, one leg per kit.
12. **AMD GPU image (ADR-1511)**: `hw_hip.py` is the HIP `GpuBackend` (devices = GPU agents from `hw_hipprobe.py`: HSA API via ctypes in a bounded child, never `HSA_AMD_AGENT_INFO_UUID`; runs pinned `ROCR_VISIBLE_DEVICES=<n>`; a GPU whose gfx target has no code object in `image/hip-targets.json` is listed, not run; path `kfd` or `none`; WSL2 `/dev/dxg` = unsupported, Linux only; no audit). `final-hip` ships only the ROCm 10.0.0 files of `image/hip-runtime.json`, copied unmodified into `/opt/vmafx/lib/rocm` with `llvm/lib` and `rocm_sysdeps/lib` beside them (RPATH layout; never patchelf); `/opt/rocm` comes from `scripts/ci/install-rocm-from-image.sh --keep-docs`. Offload targets = `HIP_GFX_TARGETS` in `docker/Dockerfile.tester`; every family of it needs a row in `hip-rows.json` (`tests/test_gpu_rows_contract.py`). Licence record = artifact `hip-image`: one component per ROCm part, texts from ROCm's `share/doc` or pinned `fetched_texts`; `rocm-sysdeps` uses `vendored_libraries` (copyleft libelf / libnuma: ELF build ID -> source archives elfutils, numactl, TheRock tree). A ROCm bump = new file names, TheRock commit, build IDs: update `hip-runtime.json` and the record together. Kernel objects `src/*_hsaco.c` take their `.hip` source's licence (`compiled_from`).
