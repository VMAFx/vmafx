# Exact twins and math-library twins

**Exact twins (ADR-1397, ADR-1428).** Twin returning CPU extractor's
bits = one fragment file `exact_twins.d/<feature>.<backend>` (`adr:` =
ADR(s) establishing exactness, must exist in `docs/adr/`; `evidence:` = one
line, fixtures + result). `cross_backend_calibration.py` builds
`EXACT_TWINS` from directory at import; loader rejects unknown key,
missing key, empty file, bad name, missing or empty directory;
`cross_backend_parity_gate.py` rejects unknown feature / backend at import.
Never list twin in code, tests or prose: no enumeration anywhere else.
Table = `docs/development/cross-backend-exact-twins.md`, GENERATED by
`scripts/docs/generate-exact-twins.py` (`make docs-fragments-write`; `--check`
in `make docs-fragments-check`). Merge conflict there -> take master's side,
regenerate.

**Depth x layout matrix.** Every listed CUDA / SYCL / HIP twin needs full
passing row in `docs/development/exact-twin-matrix.md` (8/10/12/16 bit x
420/422/444, `==` CPU, generated 357x353 fixtures). Row written only by
`scripts/ci/exact_twin_matrix.py --record` after full run of backend; never
by hand. `test_exact_twin_matrix_contract` fails on listed twin without row,
cell other than `=`, or `n/a` below 16 bit (`n/a` = CPU refuses depth). New
fragment -> run matrix on device, `--record`, commit page in same PR. Failing
cell -> defect + state row, never tolerance. Fixture bytes pinned
(`PINNED_PLANES`): generator change -> re-pin, re-record every backend.

Cell with both sides `cpu` or listed twin (`is_exact_pair`) -> tolerance 0,
source `exact:ADR-1397`, both runs get `--precision max` (default `%.6f`
hides last-bit drift). Beats calibration rows and area scaling;
explicit `--fp16-features` still wins. Unlisted backend keeps its
tolerance. Listing needs measured bit-identity + ADR. Listed twin
drifts -> fix twin, never give it tolerance back. Both sides of cell
must come from one binary: dB value goes through host `log10`,
and glibc and Intel's libimf differ by one ulp on some frames. Exact cell
also needs that binary's CPU extractor = scalar arithmetic; icx build on
AVX-512 host needs #1706.
ADR-1437 rule: list only twin exact by construction AND measured identical.
Identical on typical clips is not enough: `float_psnr_hip` (fp32 block sums)
and `float_moment_hip` (integer squares at 16 bits) matched every real clip
measured and fail on 10- to 16-bit stress input. Sweep candidate on
full-range noise at 8 / 10 / 12 / 16 bits before adding its fragment.

**Math-library twins (ADR-1426, ADR-1436, ADR-1448).** `LIBM_TWINS` in
`cross_backend_calibration.py` (`ciede`: `cuda` = 1e-9, `sycl` = 1e-9,
`hip` = 1e-9; HIP = SYCL's pair statements, gfx1036: 2 214 of 437 M pixels
off, 2 206 glibc `powf` (1 step), 8 pair rounding (1-9 steps)) =
twins running CPU's arithmetic + sum order; differing only in libm
(glibc vs device `pow` / `atan2` / `sin` / `cos` / `exp` / `powf`) and, on
SYCL (no fp64 type), in last bits of fp32 pair (1 pixel in 1.6
million vs fp64 evaluation). Cell with both sides
`cpu` or listed twin (`libm_pair_tolerance`) -> listed tolerance, source
`libm:ADR-1426`, `--precision max`. Resolved after `EXACT_TWINS`, before
calibration rows; `--fp16-features` still wins. NOT exact twin: never
move it to `EXACT_TWINS` without 0 on every fixture. Bound holds from
576x324 up (one float-step pixel weighs `8.7 * 2^-23 * (v / mean) / px`).
Listing twin needs per-pixel attribution of residual + ADR.
`speed_chroma`: `cuda` = 5e-6 (ADR-1430): device `log2` correctly rounded
(ADR-1380), CPU = C library `log2f`; glibc 2.44 -> 13 of 789 values off by
1-5 fp32 steps (1.4e-6 max), 0 with CR `log2f` preloaded. Bound sized for
scores < 16 (step <= 9.5e-7); bigger scores -> scale it, never loosen for
another reason. Gate feature `speed_chroma` = `speed_chroma_u` / `_v` /
`_uv`; other twins places=4. `hip` = 5e-6 too (ADR-1452): gfx1036, 13 of
990 values off (same frames / outputs / amounts as CUDA), 0 with CR `log2f`
preloaded; `cuda` <-> `hip` cell resolves to same bound.

`float_ms_ssim` + `float_ms_ssim_lcs`: `sycl` listed (ADR-1414, Arc A380:
every per-scale mean = CPU's). Exact cell = ONE binary on both sides ->
needs that binary's CPU extractor to be scalar arithmetic; icx build on
AVX-512 host needs #1706 (else 4 of 104 frames 1 fp32 ulp off, CPU side
wrong, not twin).
**`ssim` gate feature (ADR-1424).** `ssim` = fixed-point `integer_ssim.c`;
twins registered `integer_ssim_<backend>`, mapped in
`BACKEND_EXTRACTOR_ALIASES` (cuda, sycl, hip). CUDA host adds
per-pixel double terms in CPU's raster order (fragment `ssim.cuda`).
SYCL / HIP (> 4096 px) reduce per block -> places=4 default.

Large grids (accumulator audit): `--grid 8k` = every exact CUDA / SYCL / HIP
twin vs CPU at 8192x4320 4:4:4, 8 + 16 bit; `--grid 16k` = CPU extractor of
every exact twin at 15360x8640 4:4:4, host SIMD vs `--cpumask 0xffffffff`.
Worst-case content from SHAKE256 + constants (`worst_case_plane()`). Both
recorded in `docs/development/exact-twin-matrix.md` (markers
`exact-twin-matrix-8k:<backend>`, `exact-twin-matrix-16k:cpu`); contract
requires full row per twin in each. CPU refusal at large size is `n/a`
only for `SIZE_REFUSED` feature (cambi) and only while device refuses
too. Fixtures 1.3-6.4 GB: `--workdir` on disk, not RAM `/tmp`.
