# AdmBufferHip is passed by pointer — invariant (ADR-0759, T-HIP-ADM-ADR0759-REVERTED-2026-09-18)

`AdmBufferHip` (`integer_adm_hip.h`) is 328 bytes on LP64: six DWT band
sub-structs of four device pointers each, plus `ind_size_x` /
`ind_size_y` and eight further device-pointer fields. four
`__global__` kernels that read it —

- `adm_csf_kernel_1_4` and `i4_adm_csf_kernel_1_4`
  (`integer_adm/adm_csf.hip`, generated by two macros),
- `adm_cm_line_kernel_8` and `i4_adm_cm_line_kernel`
  (`integer_adm/adm_cm.hip`)

— take `const AdmBufferHip *__restrict__ buf_ptr`, never struct by
value. `adm_cm_reduce_line_kernel_4` does not read struct at all
and takes neither form.

**History, because this has been reverted once already.** ADR-0759
landed pointer convention in `31a51afb2` (PR #101). next merge,
`92ea978a4` (PR #102, unrelated CUDA ciede change cut from older
base), silently restored by-value signatures; AGENTS.md note
survived, so for months this file asserted invariant kernels did
not hold. If rebase or squash-merge of stale branch reintroduces
`AdmBufferHip buf` in any of four signatures, that is same
regression — re-apply pointer form, do not "fix" this note.

**Host side.** `AdmStateHip` carries `AdmBufferHip *buf_dev`, device-resident
copy of `buf`:

1. `adm_hip_upload_buf()` allocates it with `hipMalloc` and uploads
   it with `hipMemcpy(hipMemcpyHostToDevice)` **after** band-slicing
   and result-slicing blocks, once every pointer inside `s->buf` is
   final.
2. Each of four launch helpers passes `&s->buf_dev` — address
   of pointer variable, so kernel argument is 8-byte device
   address — as `args[0]`.
3. failed upload frees its unpublished local allocation. After successful
   upload, feature-name-dictionary failure releases `buf_dev`, luma,
   buffers, modules and stream in exact reverse acquisition order; normal
   close frees `buf_dev` between modules and its backing buffers. Do not
   reintroduce `fail_buf_dev:` label — zero-`goto` rule removed it.

`core/test/test_hip_adm_buffer_pointer_contract.py` binds all four device
signatures to their host `args[0]`, upload ordering and copy direction,
buffer-free reduce control, and both teardown paths. Its mutation red caps
must fail before changing this contract. `test_hip_adm_init_unwind` separately
executes dictionary failure against stub HIP runtime and protects
full BUG-092 release set and `-ENOMEM` result.

One upload serves every launch **only because nothing writes `s->buf`
after init**: it is written by allocation and slicing blocks in
`init_fex_hip()` and cleared in `close_fex_hip()`, and `submit()` hands
`&s->buf` to launch helpers without modifying it. Any future code
that changes field of `s->buf` after init must re-upload copy
before next launch, or kernels will read stale pointers.

**Measured** (ROCm 7.2 `hipcc --genco`, per-kernel metadata; same delta
on `gfx1036`, `gfx1100` and `gfx90a`):

| kernel | kernarg by value | by pointer |
| :--- | ---: | ---: |
| `adm_csf_kernel_1_4` | 856 | 536 |
| `i4_adm_csf_kernel_1_4` | 856 | 536 |
| `i4_adm_cm_line_kernel` | 904 | 584 |
| `adm_cm_line_kernel_8` | 968 | 648 |

320 bytes = `sizeof(AdmBufferHip) - sizeof(void *)`, off every launch.
`adm_cm_line_kernel_8`'s per-thread scratch also drops with it (920 →
608 bytes on `gfx1036`, 932 → 616 on `gfx90a`, 664 → 352 on `gfx1100`):
by-value copy was being spilled.

`AdmFixedParametersHip` (248 bytes) is still passed **by value** to all
four kernels. That is deferred follow-up in ADR-0759's consequences
section, not oversight — do not describe it as fixed. Do not add any
further by-value large-struct kernel parameter without ADR.

- `adm_csf_kernel_1_4`, `i4_adm_csf_kernel_1_4` (`integer_adm/adm_csf.hip`),
  `i4_adm_cm_line_kernel` and `adm_cm_line_kernel_8` (`integer_adm/adm_cm.hip`)
  take `const AdmBufferHip *__restrict__ buf_ptr`. By value, 328-byte
  struct was copied into every launch's kernel arguments.
- Host: `AdmStateHip::buf_dev` is device copy of `s->buf`.
  `adm_hip_upload_buf()` (`hipMalloc` + `hipMemcpy` HtoD) runs near end of
  `adm_hip_init_device()`, after `adm_hip_slice_bands()` and
  `adm_hip_slice_results()`. failed copy frees its unpublished local
  allocation; after publication, `adm_hip_free_buf_dev()` frees it on later
  dictionary failure and in `close_fex_hip()`.
- Launch argument = `(void *)&s->buf_dev`, address of variable that
  holds device pointer (ADR-0537 rule above).
- Precondition: nothing writes `s->buf` between init and close, and no launch
  passes modified copy. Code that changes `s->buf` after init (per-scale
  band pointers, resize) must upload it again before next launch, or
  kernels read stale pointers.
- New ADM kernels that need `AdmBufferHip` take pointer.
  `AdmFixedParametersHip` (248 bytes) and `WarpShift` are still passed by
  value; changing them needs its own measurement.
- History: #101 (`31a51afb2`) implemented this; #102 (`92ea978a4`, CUDA
  ciede change cut from older base) reverted it in merge without
  mentioning it. On conflict in these files keep pointer form;
  `grep -n 'AdmBufferHip buf' core/src/feature/hip/integer_adm/*.hip` must
  print nothing.
- Measured on gfx1036: each kernel's argument segment is 320 bytes smaller;
  per-thread scratch and VGPRs do not change because of pointer.
  936-byte scratch of `adm_cm_line_kernel_8` is VGPR spilling (239 spills at
  128-register cap), not struct. End-to-end fps is unchanged within
  noise.
- Not CUDA mirror: CUDA twin passes `AdmBufferCuda` by value and always
  has (ADR-0756 audit lists those kernels). Research-0759's statement that
  CUDA uses pointer, and ADR-0759's "matches the CUDA pattern", are wrong.
