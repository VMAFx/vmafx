# AGENTS.md — core/src/feature/rust/

Rust feature extractor crates (ADR-0707 cbindgen pilot).

## Rebase-sensitive invariants

1. **`vmafx-tad` is rlib of `vmafx-core-rs`** (`core/src/rust/staticlib`)
   since ADR-1713: libvmaf links exactly one Rust archive. Never give this
   crate `staticlib` back and never add second Meson custom target for it.

2. **Registration goes through Rust shim.** `tad_rust.c` compiled only
   with `HAVE_RUST_FEATURES` (config.h), as direct source of
   `library('vmaf')`, and `core/src/rust/shim/rust_twins.cpp` appends
   `vmaf_fex_tad` to Rust registry at `vmaf_init()`.
   `feature_extractor.cpp` must not name `vmaf_fex_tad`: also linked
   into test binaries without archive. (Before ADR-1713 gated on
   `HAVE_RUST_TAD` define file never saw, so TAD never registered.)

3. **`panic = "abort"` in `Cargo.toml` `[profile.release]`** = mandatory for
   every crate of archive (Meson always builds `--release`).

4. **Member of libvmaf-linked workspace `core/src/rust/Cargo.toml`**
   (`package.workspace = "../../../rust"`; root workspace excludes this
   directory), with `[lints] workspace = true`, `publish = false`, and zero
   dependency outside workspace (Meson cargo build is `--offline
   --locked`). See ADR-0917 for `publish = false`.

5. **No build-time cbindgen.** C wrapper re-declares three
   `vmafx_tad_*` signatures; framework's own header generated by
   `scripts/dev/rust-abi-header.sh` and committed. New Rust extractors:
   twins of C extractors; follow `docs/development/rust-extractor-framework.md`,
   not TAD hand-written wrapper.
