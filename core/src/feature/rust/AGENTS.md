# AGENTS.md — core/src/feature/rust/

Rust feature extractor crates (ADR-0707 cbindgen pilot).

## Rebase-sensitive invariants

1. **`vmafx-tad` is an rlib of `vmafx-core-rs`** (`core/src/rust/staticlib`)
   since ADR-1713: libvmaf links exactly one Rust archive. Never give this
   crate `staticlib` back and never add a second Meson custom target for it.

2. **Registration goes through the Rust shim.** `tad_rust.c` is compiled only
   with `HAVE_RUST_FEATURES` (config.h), as a direct source of
   `library('vmaf')`, and `core/src/rust/shim/rust_twins.cpp` appends
   `vmaf_fex_tad` to the Rust registry at `vmaf_init()`.
   `feature_extractor.cpp` must not name `vmaf_fex_tad`: it is also linked
   into test binaries without the archive. (Before ADR-1713 it was gated on a
   `HAVE_RUST_TAD` define that file never saw, so TAD was never registered.)

3. **`panic = "abort"` in `Cargo.toml` `[profile.release]`** = mandatory for
   every crate of the archive (Meson always builds `--release`).

4. **Member of the libvmaf-linked workspace `core/src/rust/Cargo.toml`**
   (`package.workspace = "../../../rust"`; the root workspace excludes this
   directory), with `[lints] workspace = true`, `publish = false`, and no
   dependency outside that workspace (the Meson cargo build is `--offline
   --locked`). See ADR-0917 for `publish = false`.

5. **No build-time cbindgen.** The C wrapper re-declares the three
   `vmafx_tad_*` signatures; the framework's own header is generated by
   `scripts/dev/rust-abi-header.sh` and committed. New Rust extractors are
   twins of C extractors: follow `docs/development/rust-extractor-framework.md`,
   not TAD's hand-written wrapper.
